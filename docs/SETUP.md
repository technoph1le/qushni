# Local setup

How to run Qo'shni on your computer with real sign-in. For putting it online, see [DEPLOYMENT.md](DEPLOYMENT.md).

**Needed once:** [Node.js 20+](https://nodejs.org) and [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) (`winget install Cloudflare.cloudflared` on Windows, `brew install cloudflared` on macOS).

```bash
npm run setup   # installs packages, creates frontend/.env and backend/.env
```

Values go in two files. The golden rule: anything called "secret" goes **only** in `backend/.env`.

| File | Contains | Visible to |
| --- | --- | --- |
| `backend/.env` | Secret keys | The server only |
| `frontend/.env` | Public keys | Everyone (they end up in the website) |

> Joining an existing team? Ask a teammate for the values of both `.env` files (share them privately, never in a chat group or repository), paste them in and skip to step 5.

---

## 1. Supabase project and database

1. [supabase.com/dashboard](https://supabase.com/dashboard) → **New project**, region **Central EU (Frankfurt)**.
2. **SQL Editor → New query**: paste each file from [`supabase/migrations/`](../supabase/migrations/) **in order** and click **Run**.
3. **Project Settings → API Keys**:

| Copy | Paste into |
| --- | --- |
| Project URL | `VITE_SUPABASE_URL` (frontend) and `SUPABASE_URL` (backend) |
| Publishable key `sb_publishable_…` | `VITE_SUPABASE_ANON_KEY` (frontend) |
| Secret key `sb_secret_…` | `SUPABASE_SERVICE_ROLE_KEY` (backend only) |

## 2. Google sign-in

1. [Google Cloud Console](https://console.cloud.google.com) → **Google Auth Platform** → create a **Web application** client:
   - Authorized JavaScript origins: `http://localhost:5173`
   - Authorized redirect URIs: `https://<project-id>.supabase.co/auth/v1/callback`
2. Paste the **Client ID** and **Client secret** into Supabase → **Authentication → Sign In / Providers → Google**. These go in the Supabase dashboard, not in a `.env` file.
3. Supabase → **Authentication → URL Configuration**:
   - Site URL: `http://localhost:5173`
   - Redirect URLs: `http://localhost:5173/**` and `https://*.trycloudflare.com/**`. The second one makes Google sign-in work on share links.

## 3. Telegram bot (for development)

Create a **separate development bot**, so local testing never touches the production bot:

1. [@BotFather](https://t.me/BotFather) → `/newbot` → e.g. `qoshni_dev_bot`.
2. Put its token in `TELEGRAM_BOT_TOKEN` and its username (without @) in `TELEGRAM_BOT_USERNAME` (backend). `TELEGRAM_WEBHOOK_SECRET` was already generated by `npm run setup`.

## 4. Check the files

`frontend/.env` keeps `VITE_API_URL=/api` for local development. `backend/.env` keeps `FRONTEND_URL=http://localhost:5173`. Leave `PUBLIC_API_URL` empty locally.

## 5. Run it

```bash
npm run dev
```

The terminal prints:

```
  Qo'shni is running
  Website:     http://localhost:5173
  Backend:     http://localhost:8787
  Share link:  https://something.trycloudflare.com
```

`npm run dev` also points your dev bot at the share link automatically, so phone sign-in works. Stop everything with **Ctrl+C**.

**Test checklist:**
- [ ] Google sign-in returns you to the site, signed in.
- [ ] Phone sign-in: enter your +998 number → the bot sends a code → enter it.
- [ ] Post a room with photos; it appears on the home page.
- [ ] Open the share link on your phone.

## Sharing with the team

Send the **Share link** from the terminal. It works on any device while your terminal is running, and the address changes each time you restart `npm run dev`. Testers use your real database, so their test accounts and listings are real rows. Delete them from Supabase when you're done.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| "Dependencies are missing" | Run `npm run setup`. |
| Port 5173 or 8787 already in use | Another copy is running; close it, or its terminal. |
| No share link | Install cloudflared, then run `npm run dev` again. Cloudflare sometimes refuses briefly; retry after a minute. |
| Google sign-in returns to the login page with an error | The message on the page tells you which setting is wrong; usually the Client secret in Supabase. |
| Phone code never arrives | Make sure you messaged the **dev** bot, and that `npm run dev` printed "Telegram bot … now delivers to this computer". |
