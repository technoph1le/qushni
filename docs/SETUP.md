# Local setup

How to run Qo'shni on your computer with real sign-in. For putting it online, see [DEPLOYMENT.md](DEPLOYMENT.md).

**Needed once:** [Node.js 20.9+](https://nodejs.org) and [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) (`winget install Cloudflare.cloudflared` on Windows, `brew install cloudflared` on macOS).

```bash
npm run setup   # installs packages, creates .env.local
```

All settings live in **one file, `.env.local`**, in the project root. It is git-ignored. Only variables starting with `NEXT_PUBLIC_` reach the browser; everything else stays on the server.

> Joining an existing team? Ask a teammate for their `.env.local` values (share them privately, never in a group chat or repository), paste them in, use **your own dev bot** (step 3) and skip to step 4.

---

## 1. Supabase project and database

1. [supabase.com/dashboard](https://supabase.com/dashboard) → **New project**, region **Central EU (Frankfurt)**.
2. **SQL Editor → New query**: paste each file from [`supabase/migrations/`](../supabase/migrations/) **in order** and click **Run**.
3. **Project Settings → API Keys**, into `.env.local`:

| Copy | Paste as |
| --- | --- |
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_URL` |
| Publishable key `sb_publishable_…` | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` |
| Secret key `sb_secret_…` | `SUPABASE_SERVICE_ROLE_KEY` (server only — never with a `NEXT_PUBLIC_` name) |

## 2. Google sign-in

1. [Google Cloud Console](https://console.cloud.google.com) → **Google Auth Platform** → create a **Web application** client:
   - Authorized JavaScript origins: `http://localhost:5173`
   - Authorized redirect URIs: `https://<project-id>.supabase.co/auth/v1/callback`
2. Paste the **Client ID** and **Client secret** into Supabase → **Authentication → Sign In / Providers → Google**. These go in the Supabase dashboard, not in `.env.local`.
3. Supabase → **Authentication → URL Configuration**:
   - Site URL: `http://localhost:5173`
   - Redirect URLs: `http://localhost:5173/**` and `https://*.trycloudflare.com/**`. The second one makes Google sign-in work on share links.

## 3. Telegram bot (for development)

Use a **separate development bot**, so local testing never touches the production bot:

1. [@BotFather](https://t.me/BotFather) → `/newbot` → e.g. `qoshni_dev_bot`.
2. In `.env.local`: its token as `TELEGRAM_BOT_TOKEN`, and its username without @ as `TELEGRAM_BOT_USERNAME`. `TELEGRAM_WEBHOOK_SECRET` was already generated by `npm run setup`.

## 4. Run it

```bash
npm run dev
```

The terminal prints:

```
  Qo'shni is running
  Local:       http://localhost:5173
  Share link:  https://something.trycloudflare.com
```

`npm run dev` also points your dev bot at the share link automatically, so phone sign-in works. Stop with **Ctrl+C**.

**Test checklist:**
- [ ] Google sign-in returns you to the site, signed in.
- [ ] Phone sign-in: enter your +998 number → the bot sends a code → enter it.
- [ ] Post a room with photos; it appears on the home page.
- [ ] Open the share link on your phone.

## Sharing with the team

Send the **Share link** from the terminal. It works while your terminal is running, and the address changes each time you restart `npm run dev`. Testers use your real database, so their test accounts and listings are real rows. Delete them from Supabase afterwards.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| "Dependencies are missing" / ".env.local is missing" | Run `npm run setup`. |
| "Configuration error" on the page | `NEXT_PUBLIC_SUPABASE_URL` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` is empty in `.env.local`. Restart `npm run dev` after editing. |
| Port 5173 already in use | Another copy is running; close its terminal. |
| No share link | Install cloudflared and run `npm run dev` again. Cloudflare sometimes refuses briefly; the runner retries 3 times. |
| Google sign-in returns to the login page with an error | The message on the page names the problem; usually the Client secret in Supabase. |
| Phone code never arrives | Make sure you messaged the **dev** bot, and that `npm run dev` printed "Telegram bot … now delivers to this computer". |
| Log says "rate limit check failed" | Run the latest file in `supabase/migrations/` (rate limits). Sign-in still works meanwhile. |
